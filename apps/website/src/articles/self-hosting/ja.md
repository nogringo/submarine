# 自分と身近な人のためにサーバーを運営する

Submarine には独自のサーバーがありません。初期設定では、保管庫は独立した運営者による公開の Nostr リレーにコピーされます。自分や信頼できる人が運営するサーバーを追加すれば、保管庫のコピーを知っている人のもとに置けます。

## 自分と身近な人のために

1 台のサーバーで、身近な人全員の保管庫を保存できます。サーバーのアドレスを伝えれば、相手は手順 3 と同じように自分の保管庫に追加できます。

- サーバーを止めても、相手は何も失いません。保管庫はほかのリレーにも、相手の各デバイスにも残っています。
- サーバーに見えるのは暗号化されたデータだけです。相手のパスワードを読むことも、変更することもできません。ほかのリレーと同じく、相手の IP アドレスは見えます。
- 友人もサーバーを運営しているなら、お互いのサーバーを追加しましょう。それぞれが相手のコピーを保存することになります。

## 必要なもの

- インターネットからアクセスできるマシン。レンタルサーバーや自宅のコンピューターなど。
- そのマシンを指すドメイン名と HTTPS。
- 以下の 2 つのサーバーをインストールするための Docker。

## 1. リレーをインストールする

[nostr-relay](https://github.com/nogringo/nostr-relay) を、その手順に沿ってインストールします。ほとんどのリレーと違い、保管庫のデータを保管庫の鍵を持つ人にしか渡さず、そのデータを削除することもできます。

前段に、元の Host ヘッダーをそのまま転送する HTTPS プロキシを置いてください。Submarine が保管庫の鍵を持っていることをリレーが確認するために必要です。

アドレスは `wss://relay.example.com` のように `wss://` で始まります。

## 2. ファイルサーバーをインストールする

アイテムに添付したファイルは、リレーではなくファイルサーバーに保存されます。ファイルのコピーも残すには、[blossom-server](https://github.com/hzrd149/blossom-server) を、その手順に沿ってインストールします。

設定ファイルの `storage` の下にあるルールの先頭に、次のルールを追加してください。

```yaml
- type: application/octet-stream
  expiration: 100 years
```

これで Submarine の暗号化されたファイルは保存されます。このルールがないと、設定例では 1 週間誰も開かなかったファイルが削除されます。

アドレスは `https://blossom.example.com` のように `https://` で始まります。

## 3. 保管庫に追加する

1. 保管庫の設定を開き、**同期**の**リレー**を開きます。
2. **リレーを追加**を押し、リレーのアドレスを入力して**非公開にする**をオンにし、**追加**を押します。
3. **保存**を押します。
4. 保管庫の設定に戻って**ファイルサーバー**を開き、同じように**サーバーを追加**でファイルサーバーを追加します。

保管庫ごとに同じ操作をしてください。**非公開にする**を選ぶと、アドレスは保管庫の中で暗号化されます。そうしないと、この保管庫があなたのサーバーに保存されていることを誰でも確認でき、誰の保管庫なのか推測できてしまいます。

## 公開リレーもいくつか残す

自分のリレーと一緒に、公開リレーもいくつか残しておきましょう。サーバーが止まったりデータを失ったりしても、保管庫はそちらに残っています。また、各デバイスにもそれぞれのコピーがあります。
