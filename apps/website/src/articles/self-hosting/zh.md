# 为自己和身边的人运行服务器

Submarine 没有自己的服务器：默认情况下，您的密码库会复制到由独立运营者运行的公共 Nostr 中继上。您可以添加由您自己或您信任的人运行的服务器，这样密码库的副本就保存在您认识的人那里。

## 为自己和身边的人

一台服务器就能保存您身边所有人的密码库：把它的地址告诉他们，他们按照第 3 步把它添加到自己的密码库中即可。

- 即使您停掉服务器，他们也不会丢失任何东西：他们的密码库仍然在其他中继上，也在他们的每台设备上。
- 您的服务器只能看到加密数据：它既不能读取他们的密码，也不能修改。和任何中继一样，它能看到他们的 IP 地址。
- 如果您的朋友也运行服务器，就互相添加对方的服务器：每个人都为对方保留一份副本。

## 您需要什么

- 一台可以从互联网访问的机器，例如租用的服务器或您家里的电脑。
- 一个指向这台机器的域名，并启用 HTTPS。
- Docker，用来安装下面的两个服务器。

## 1. 安装中继

按照 [nostr-relay](https://github.com/nogringo/nostr-relay) 的说明安装它。与大多数中继不同，它只把密码库的数据交给持有密码库密钥的人，并且允许您删除这些数据。

在它前面放一个转发原始 Host 请求头的 HTTPS 代理：中继需要这个请求头来确认 Submarine 持有密码库密钥。

它的地址以 `wss://` 开头，例如 `wss://relay.example.com`。

## 2. 安装文件服务器

附加到项目的文件保存在文件服务器上，而不是中继上。如果您也想保留这些文件的副本，请按照 [blossom-server](https://github.com/hzrd149/blossom-server) 的说明安装它。

在它的配置文件中，把下面这条规则添加到 `storage` 下规则的最前面：

```yaml
- type: application/octet-stream
  expiration: 100 years
```

这样，Submarine 的加密文件就会被保留。如果没有这条规则，示例配置会删除一周内无人打开过的任何文件。

它的地址以 `https://` 开头，例如 `https://blossom.example.com`。

## 3. 把它们添加到密码库

1. 打开密码库设置，在**同步**下打开**中继**。
2. 点击**添加中继**，输入您的中继地址，打开**保持私密**，然后点击**添加**。
3. 点击**保存**。
4. 回到密码库设置，打开**文件服务器**，用同样的方式通过**添加服务器**添加您的文件服务器。

对您的每个密码库都这样做。**保持私密**会在密码库中加密这个地址：否则，任何人都能看到这个密码库保存在您的服务器上，并猜出它属于谁。

## 保留几个公共中继

在您自己的中继之外，保留几个公共中继：即使您的服务器停止运行或丢失数据，密码库仍然在它们上面。此外，您的每台设备也各自保留一份副本。
